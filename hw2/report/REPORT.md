## 1. Условие задачи

За круглым столом сидят N философов. Каждый размышляет, затем пытается поесть. Для еды нужны две соседние вилки; одной вилкой одновременно пользуется только один философ. После еды вилки освобождаются. Нужно организовать работу философов в отдельных потоках, предотвратить взаимоблокировку и отслеживать долгое ожидание.

## 2. Потоки и синхронизация

Каждому философу соответствует поток `pthread`, который повторяет цикл: размышление, получение вилок, еда, освобождение вилок. Главный поток следит за ожиданием и условиями завершения, затем ждёт рабочих через `pthread_join`. Всего работают N+1 потоков. Вилки хранятся в общих структурах; собственное поведение и отдельные потоки им не нужны.

Основная программа `philosophers-sem` использует общий мьютекс и по одному семафору уведомления на философа. Мьютекс защищает владельцев вилок, состояния философов, статистику и вывод. Если вилка занята, поток отмечает ожидание, отпускает мьютекс и вызывает `sem_wait`. При освобождении вилка передаётся ожидающему соседу, который получает уведомление. После пробуждения условие проверяется повторно. Во время размышления и еды мьютекс не удерживается.

В дополнительной программе `philosophers-cond` семафоры заменены условными переменными. `pthread_cond_wait` отпускает мьютекс на время ожидания и захватывает его перед возвратом. Остальная логика у двух версий общая.

Философу p нужны вилки p и `(p+1) mod N`. Стратегия `ordered` берёт сначала вилку с меньшим номером. Поэтому номера вилок в цепочке ожидания возрастают и цикл не возникает. Стратегия `naive` берёт сначала левую вилку и может привести к взаимоблокировке. Для её демонстрации параметр `-b` заставляет всех получить первую вилку до запроса второй. Главный поток обнаруживает цикл ожидания и останавливает программу.

## 3. Интерфейс

Параметры задаются через командную строку и разбираются с помощью `getopt`. Время указывается в реальных миллисекундах.

| Параметр | Назначение | По умолчанию |
| --- | --- | --- |
| `-n N` | Число философов, от 2 до 256 | 5 |
| `-c N` | Число приёмов пищи у каждого; 0 — без ограничения | 3 |
| `-t MIN-MAX` | Длительность размышления | 100–500 |
| `-e MIN-MAX` | Длительность еды | 200–400 |
| `-s NAME` | Стратегия `ordered` или `naive` | `ordered` |
| `-w N` | Порог предупреждения об ожидании | 2000 |
| `-T N` | Ограничение времени; 0 — без ограничения | 0 |
| `-r N` | Начальное значение генератора случайных чисел | 42 |
| `-d N` | Дополнительная пауза после размышления и перед следующим циклом | 0 |
| `-l FILE` | Файл журнала | `philosophers-hw2.log` |
| `-b` | Барьер первых вилок, только для `naive` | Выключен |
| `-h` | Справка | — |

Для `-t` и `-e` можно указать одно число вместо диапазона. Неверные параметры отклоняются до создания потоков.

События выводятся в терминал и журнал: время от старта, номер философа и действие. Файл открывается через `open`, запись выполняется через `vdprintf`. В конце выводится статистика приёмов пищи и ожидания. Если ожидание достигает `-w`, появляется предупреждение; работа продолжается.

## 4. Запуск и завершение

Сборка и запуск из корня проекта:

```sh
make -C hw2
cd hw2
./bin/philosophers-sem
./bin/philosophers-cond
```

Для сборки нужны компилятор C17, библиотека pthread и `make`.

В обычном режиме программа заканчивает работу, когда каждый философ поел `-c` раз. При `-c 0` она работает до ограничения `-T` или сигнала. При остановке ожидающие потоки пробуждаются, возвращают вилки и завершаются. Главный поток ждёт их через `pthread_join`, выводит статистику и освобождает ресурсы.

Коды завершения:

- `0` — все циклы выполнены или достигнут предел времени при `-c 0`;
- `1` — ошибка открытия журнала, выделения ресурсов или записи;
- `2` — неверные параметры;
- `3` — обнаружена взаимоблокировка;
- `4` — ошибка состояния или синхронизации;
- `5` — время истекло до выполнения всех циклов;
- `130` — прерывание по Ctrl+C (`SIGINT`), `143` — по `SIGTERM`.

Обработчики сигналов только сохраняют номер сигнала. Остановку потоков выполняет основной код программы.

## 5. Результаты

Пример обычного запуска:

```sh
./bin/philosophers-sem -n 5 -c 2 -t 5-10 -e 10-15 -w 20 -r 42
```

Фрагмент полученного журнала и статистики:

```text
[t=    30] Философ 0: ВНИМАНИЕ: ждёт 20 мс, предел 20 мс
[t=    36] Философ 0: начал есть (ждал 26 мс, будет есть 12 мс), цикл 1
Всего поели: 10 раз
Среднее ожидание: 11 мс
Самое долгое ожидание: 30 мс
Вилок занято после завершения: 0
Код завершения: 0
```

Все философы поели по два раза. При повторном запуске порядок событий и измеренное ожидание могут отличаться из-за планирования потоков.

Для проверки взаимоблокировки использовалась команда:

```sh
./bin/philosophers-cond -n 5 -c 2 -t 0 -e 1 -s naive -b
```

Обнаружена цепочка ожидания 0 → 1 → 2 → 3 → 4 → 0. Программа завершилась с кодом 3, все вилки были освобождены.

Автотесты запускаются командой `make test` из папки `hw2/`; нужен Python 3.9 или новее. Они проверяют работу с вилками, завершение по времени и сигналам, обе стратегии и ошибки входных данных. На Linux пройдены все 42 проверки обеих версий. Скрипт и результаты находятся в `tests/`.
