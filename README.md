## 1. Постановка задачи

За круглым столом сидят философы. Каждый из них некоторое время размышляет, затем пытается поесть. Между соседними философами лежит одна вилка, поэтому для еды необходимо получить две вилки: слева и справа. Закончив есть, философ освобождает обе вилки и возвращается к размышлению.

Сложность задачи связана с порядком получения вилок. Если все философы возьмут по одной вилке и станут ждать вторую, никто из них не сможет продолжить. Такое состояние называется взаимоблокировкой. В программе требуется предусмотреть порядок действий, при котором она не возникает, а также отслеживать слишком долгое ожидание.

При запуске задаются число философов, число циклов, длительность размышления и еды, стратегия получения вилок и допустимое время ожидания.

## 2. Устройство модели

### Основные сущности

**Стол (`Table`).** Стол объединяет философов и вилки в одну модель. Их количество совпадает, нумерация начинается с нуля. Философу с номером p доступны вилки p и (p+1) mod N, то есть у последнего философа соседними будут вилки N-1 и 0. В структуре `Table` хранятся массивы философов и вилок, параметры запуска, очередь событий, текущее модельное время и состояние генератора случайных чисел.

**Философ (`Philosopher`).** Философ может размышлять, ожидать вилки, есть или завершить работу. В начале моделирования все философы размышляют. По окончании размышления философ становится голодным и запрашивает вилки в порядке, заданном выбранной стратегией. Получив обе вилки, он начинает есть. Затем освобождает их и переходит к следующему циклу либо выходит из-за стола, если поел нужное число раз. Для каждого философа сохраняются число завершённых приёмов пищи, момент начала ожидания и статистика ожидания.

**Вилка (`Fork`).** Вилка может быть свободна или занята одним из двух соседей. Если второй сосед запрашивает занятую вилку, его номер записывается в поле ожидания. При освобождении вилка сразу передаётся ожидающему философу. Очередь из нескольких ожидающих не нужна, поскольку одной вилкой пользуются только два соседа.

### Модельное время и события

Программа написана на C и работает последовательно, без потоков. Действия философов представлены событиями. Главный цикл выбирает из очереди ближайшее событие, устанавливает его время в качестве текущего и вызывает обработчик. Обработчик меняет состояние модели и при необходимости добавляет следующие события. Например, при начале еды длительностью 300 единиц её окончание назначается на момент на 300 единиц позже текущего.

Используются пять видов событий:

- `EV_THINK_END` — окончание размышления и переход к ожиданию вилок;
- `EV_FORK_REQUEST` — запрос одной вилки;
- `EV_EAT_END` — окончание еды и освобождение вилок;
- `EV_WAIT_CHECK` — проверка длительности ожидания;
- `EV_TIME_LIMIT` — достижение заданного ограничения времени.

События с одинаковым временем обрабатываются в порядке добавления. При одинаковых параметрах и начальном значении генератора (`seed`) ход моделирования повторяется. Длительность размышления и еды выбирается генератором из заданных диапазонов.

Запросы первой и второй вилки оформлены отдельными событиями. Между ними могут выполняться запросы других философов. Это позволяет воспроизвести ситуацию, когда каждый философ уже получил одну вилку, но ещё не получил вторую.

### Порядок получения вилок

Основная стратегия, `ordered`, задаёт общий порядок: сначала берётся вилка с меньшим номером, затем с большим. У последнего философа это меняет порядок получения вилок — он начинает с вилки 0. Если философ уже держит одну вилку и ждёт вторую, номер второй всегда больше номера первой. Поэтому цепочка ожидания не может замкнуться и взаимоблокировка не возникает.

В стратегии `naive` каждый философ сначала запрашивает левую вилку, затем правую. Этот вариант используется для демонстрации взаимоблокировки и проверки того, что программа её обнаруживает.

### Проверка состояния

После обработки действий философов программа проверяет, что каждый едящий философ держит две вилки, а размышляющие и завершившие работу не держат ни одной. Также проверяется, что ожидаемая вилка действительно занята.

Для поиска взаимоблокировки программа проходит по цепочке ожидания: от философа к владельцу нужной ему вилки, затем к следующему владельцу. Возвращение к исходному философу означает, что цепочка замкнулась. В этом случае моделирование останавливается, а в журнал выводятся участники взаимоблокировки.

Если к достижению допустимого времени ожидания философ всё ещё не получил обе вилки, выводится предупреждение. Число таких случаев учитывается отдельно для каждого философа. После предупреждения моделирование продолжается.

Разбор параметров, открытие журнала и обработка сигналов находятся в `src/main.c`. Модель стола, обработчики событий, проверки и статистика описаны в `src/sim.c` и `src/sim.h`. Очередь событий вынесена в `src/event.c` и `src/event.h`, а генератор псевдослучайных чисел xorshift64* — в `src/rng.c` и `src/rng.h`.

## 3. Интерфейс

Сообщения о действиях философов содержат модельное время, номер философа и описание действия. Например:

```
[t=   290] Философ 1: вилка 2 занята философом 2, ждёт
[t=   330] Философ 2: закончил есть (поел раз: 1)
[t=   330] Философ 2: положил вилку 2
[t=   330] Философ 1: получил вилку 2
```

Для удобства наблюдения между событиями сделана пауза, по умолчанию 100 мс. Она не влияет на модельное время. В конце программа выводит число приёмов пищи, суммарное, среднее и максимальное время ожидания для каждого философа.

Сообщения о моделировании выводятся на экран и в файл журнала через `vdprintf`. Файл открывается системным вызовом `open`.

Параметры командной строки разбираются с помощью `getopt`. Значения по умолчанию указаны в скобках:

```
-n N        число философов, от 2 до 1000 (5)
-c N        число приёмов пищи для каждого, 0 - без ограничения (3)
-t MIN-MAX  время размышления (100-500)
-e MIN-MAX  время еды (200-400)
-s NAME     ordered или naive (ordered)
-w N        допустимое время ожидания (2000)
-T N        ограничение модельного времени, 0 - нет (0)
-r N        начальное значение генератора случайных чисел (42)
-d N        пауза между событиями в мс (100)
-l FILE     лог-файл (philosophers.log)
-h          справка
```

Время размышления, еды и ожидания задаётся в условных единицах модели. Для `-t` и `-e` можно указать одно число вместо диапазона. Параметр `-d` задаёт реальную паузу в миллисекундах; при `-d 0` программа выполняется без этих пауз.

## 4. Запуск и завершение

```sh
make
./bin/philosophers
./bin/philosophers -n 7 -c 5 -s naive
```

В обычном режиме работа завершается, когда все философы поели заданное число раз. При `-c 0` число циклов не ограничено: моделирование можно закончить по времени с помощью `-T` или прервать сигналом. Обработчики `SIGINT` и `SIGTERM` только сохраняют номер сигнала. Остановка, вывод состояния стола и статистики выполняются в основном коде программы.

Код завершения зависит от причины остановки:

| Код | Причина |
| --- | --- |
| 0 | Все циклы завершены либо достигнут предел времени при `-c 0` |
| 1 | Не удалось открыть журнал или выделить память |
| 2 | Некорректные параметры запуска |
| 3 | Обнаружена взаимоблокировка |
| 4 | Нарушены правила модели или очередь событий опустела до завершения работы |
| 5 | Достигнут предел времени, но заданное число циклов выполнили не все философы |
| 130 | Прерывание сигналом `SIGINT` (Ctrl+C) |
| 143 | Прерывание сигналом `SIGTERM` |

## 5. Результаты

Для проверки взаимоблокировки использовались параметры `-s naive -t 100 -e 200`. Все философы закончили размышление в момент 100, получили левые вилки и запросили правые. Программа обнаружила замкнутую цепочку ожидания и завершилась с кодом 3:

```
[t=   100] ВЗАИМОБЛОКИРОВКА:
    философ 0 ждёт вилку 1, её держит философ 1
    философ 1 ждёт вилку 2, её держит философ 2
    философ 2 ждёт вилку 3, её держит философ 3
    философ 3 ждёт вилку 4, её держит философ 4
    философ 4 ждёт вилку 0, её держит философ 0
```

При замене `naive` на `ordered` с остальными теми же параметрами все философы завершили заданные циклы. Философ 4 сначала запрашивает вилку 0 и ожидает её, не занимая вилку 4. Благодаря этому философ 3 получает обе вилки и начинает есть, после чего освобождает их для соседей.

При запуске с параметрами по умолчанию получена следующая статистика:

```
Философ 0: поел 3 раз, ждал всего 324, в среднем 108, максимум 208
Философ 1: поел 3 раз, ждал всего 485, в среднем 161, максимум 351
Философ 2: поел 3 раз, ждал всего 243, в среднем 81, максимум 228
Философ 3: поел 3 раз, ждал всего 335, в среднем 111, максимум 235
Философ 4: поел 3 раз, ждал всего 181, в среднем 60, максимум 127
Всего поели: 15 раз
Среднее ожидание: 104
Самое долгое ожидание: 351 (допустимо 2000)
```

Все пять философов поели по три раза. Максимальное ожидание составило 351 единицу модельного времени и не достигло установленного предела 2000.

При уменьшении допустимого ожидания до 150 единиц (`-w 150`) в журнале появились предупреждения:

```
[t=  1409] Философ 2: ВНИМАНИЕ: ждёт уже 150, это предел ожидания
```

Отдельно проверялось завершение по времени. При параметрах `-c 100 -T 1500` ни один философ не успел выполнить все 100 циклов. Программа завершилась с кодом 5 и вывела состояние стола:

```
Время вышло, а поели все циклы только 0 философов из 5.
Состояние стола (t=1500):
  Философ 0: ест, вилок в руках: 2
  Философ 1: голоден, вилок в руках: 0, ждёт вилку 1
  Философ 2: ест, вилок в руках: 2
  Философ 3: думает, вилок в руках: 0

```

## 6. Тестирование

Автоматические проверки находятся в `tests/run_tests.sh` и запускаются командой `make test`. Скрипт проверяет коды завершения и наличие ожидаемых сообщений в выводе программы и журнале.

В набор входят обычный запуск, работа с 2 и 50 философами, сравнение стратегий при одновременном запросе вилок, предупреждение о долгом ожидании и два варианта завершения по времени. Отдельно проверяются пять случаев неверных параметров, совпадение журналов при одинаковом `seed` и обработка Ctrl+C с сохранением статистики. Кроме того, выполняются 100 запусков с разными значениями `seed`, числом философов и диапазонами времени.
