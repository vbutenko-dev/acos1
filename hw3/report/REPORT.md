## 1. Условие задачи

За круглым столом сидят N философов, между соседями лежит по одной вилке. Философ размышляет, получает обе соседние вилки, ест и освобождает их. Одной вилкой одновременно пользуется только один философ. Требуется реализовать модель на C для Linux с отдельным процессом для каждого философа, исключить взаимоблокировку и контролировать длительное ожидание.

Подготовлены три реализации: дочерние процессы с именованными POSIX-семафорами; дочерние процессы с неименованными POSIX-семафорами в общей памяти; независимо запускаемые процессы с именованными POSIX-семафорами. Во всех вариантах данные хранятся в POSIX shared memory.

## 2. Процессы и синхронизация

В `philosophers-named` и `philosophers-unnamed` родитель создаёт ресурсы и запускает N философов через fork. Он контролирует остановку, ожидает завершения детей и удаляет общие ресурсы.

В независимом варианте `table` создаёт стол, но не запускает философов через fork. Экземпляры `philosopher` запускаются отдельно с общим ключом и уникальными номерами от 0 до N-1. `table` выводит «Стол готов: KEY» и ждёт регистрации всех участников не дольше 30 секунд. Время модели отсчитывается после регистрации всех философов.

Общая память содержит параметры, владельцев вилок, FIFO-очередь голодных, состояния, статистику и признак остановки. Философу p нужны вилки p и (p+1) mod N. Вилки представлены данными: собственного поведения у них нет.

Общий семафор с начальным значением 1 защищает состояние. По одному семафору уведомления приходится на каждого философа. Ожидание уведомления, размышление и еда выполняются без удержания общей блокировки. Поэтому философы с непересекающимися парами вилок могут есть одновременно.

В именованном варианте семафоры открываются по общим именам. В неименованном объекты `sem_t` находятся в разделяемой памяти и создаются с признаком межпроцессного использования. Алгоритм у всех философов одинаковый.

## 3. Стратегия FIFO

Голодный философ помещается в конец очереди. Под общей блокировкой проверяется её голова. Если обе нужные вилки свободны, они одновременно закрепляются за философом, он удаляется из очереди и получает уведомление. Затем проверяется следующий участник. Если голове не хватает вилки, выдача приостанавливается до изменения состояния.

Философ не удерживает одну вилку, ожидая вторую. Поэтому цикл взаимного ожидания вилок не возникает. Изменение владельцев под общим семафором исключает одновременную выдачу одной вилки двум участникам.

Новые запросы не обгоняют старые. При конечном времени еды и продолжающемся выполнении процессов ожидающие получают возможность обслуживания. Дополнительно превышение максимального ожидания останавливает модель с диагностикой. Компромисс FIFO: следующий философ иногда ждёт за головой очереди даже при свободной собственной паре. Это принято ради простоты и понятного порядка.

## 4. Интерфейс и запуск

Нужны Linux, компилятор C17, make и POSIX API. Сборка из корня репозитория:

```sh
make -C hw3
cd hw3
```

Параметры `philosophers-named`, `philosophers-unnamed` и `table`:

```text
-n N         философов и вилок, 2..64;
-c N         приёмов пищи каждого, 0 — без ограничения;
-t MIN-MAX   время размышления в миллисекундах;
-e MIN-MAX   время еды в миллисекундах;
-s fifo      стратегия получения вилок;
-w MS        максимальное ожидание вилок, больше нуля;
-T MS        предел времени, 0 — без ограничения;
-r SEED      начальное значение генератора;
-l FILE      файл журнала;
-h           справка.
```

Вместо диапазона времени допустимо одно число. Время ограничено 86400000 мс, число циклов — `INT_MAX`, seed — UINT64_MAX. Значения по умолчанию приведены в справке. Только `table` принимает `-k KEY`: до 20 ASCII-букв, цифр, символов '_' и '-'. `philosopher` принимает позиционные аргументы KEY ID.

Именованные семафоры:

```sh
./bin/philosophers-named -n 5 -c 3 -t 20-40 -e 20-40 -w 5000 -T 10000 -r 42 -l named.log
```

Неименованные семафоры:

```sh
./bin/philosophers-unnamed -n 5 -c 3 -t 20-40 -e 20-40 -w 5000 -T 10000 -r 42 -l unnamed.log
```

Независимый вариант: открыть четыре терминала в папке hw3. В первом:

```sh
./bin/table -k demo -n 3 -c 2 -t 20-40 -e 20-40 -w 5000 -T 10000 -r 42 -l independent.log
```

Во втором:

```sh
./bin/philosopher demo 0
```

В третьем:

```sh
./bin/philosopher demo 1
```

В четвёртом:

```sh
./bin/philosopher demo 2
```

После регистрации всех участников начинается моделирование. Для другого стола используется другой ключ. Для неограниченного числа циклов задаётся `-c 0`; остановка возможна по Ctrl+C или пределу -T.

Вывод показывает время, номер философа, начало и конец размышления, голод, запрос и получение каждой вилки, начало и конец еды, возврат вилок и ожидание. Итоговая статистика отражает выполненные циклы и состояние вилок. Порядок событий при одном seed может различаться из-за планирования процессов.

## 5. Завершение

Обычное завершение происходит после всех циклов. При остановке ожидающие пробуждаются, участники возвращают вилки и выходят. В fork-версиях родитель ожидает детей; в независимой ресурсами владеет table.

Обработчики `SIGINT/SIGTERM` только сохраняют сигнал. Остановка и освобождение выполняются обычным кодом. Сигнал независимому философу вызывает общую остановку через состояние стола.

Код 0 означает выполнение всех циклов либо предел времени в режиме -c 0. Превышение ожидания и истечение времени до выполнения конечных циклов дают код 5. После завершения участников владелец уничтожает семафоры и удаляет POSIX shared memory.

## 6. Результаты

Проверка выполнена в Linux aarch64, Debian 12, GCC 12.2.0. Все четыре исполняемых файла собраны как C17 с `-Wall -Wextra -Wpedantic` без предупреждений.

Автоматические проверки запускаются командой `make test` из hw3. Нужен Python 3.9+. Пройдено 29 из 29 проверок. Сводка и примеры журналов: [результаты проверок](../tests/results/summary.json), [именованные семафоры](../tests/results/named-example.txt), [неименованные семафоры](../tests/results/unnamed-example.txt), [независимые процессы](../tests/results/independent-example.txt); повторный запуск создаёт новые результаты в tests/out.

Для каждой из трёх реализаций базовый тест использовал параметры:

```text
-n 5 -c 3 -t 0-2 -e 1-3 -w 3000
```

В named, unnamed и independent каждый из пяти философов поел ровно 3 раза; всего 15 приёмов пищи. Все три запуска завершились с кодом 0, занятых вилок после завершения — 0. Фрагмент реального журнала named:

```text
[t=     6] Философ 4: просит вилку 4
[t=     6] Философ 4: просит вилку 0
[t=     6] Философ 4: получил вилку 4
[t=     6] Философ 4: получил вилку 0
[t=     6] Философ 4: начал есть (ждал 0 мс, будет есть 3 мс), цикл 1
```

Тесты проверяют владельцев вилок по событиям журнала: нельзя выдать занятую вилку, начать еду без двух вилок или вернуть вилки до окончания еды. Проверяются итоговые счётчики, два философа, 16 философов по 20 циклов без пауз и одновременная еда несоседей.

В конечном режиме предел `-T 30` завершил все три реализации с кодом 5. При `-c 0` предел `-T 60` дал код 0. При `-w 10` и еде 500 мс превышение ожидания остановило модель с кодом 5. `SIGINT` и `SIGTERM` дали коды 130 и 143. Отдельно `SIGINT` отправлялся ожидающему `philosopher`: весь независимый стол остановился с кодом 130.

После каждого запуска проверено отсутствие новых объектов семафоров и общей памяти в /dev/shm. После полного набора `/dev/shm` пуст. Повторное создание стола с занятым ключом и запуск второго философа с тем же номером отклонены с кодом 1; действующий стол продолжил работу.
